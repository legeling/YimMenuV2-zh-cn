# 版本与发布规则

中文维护版使用 `VERSION` 作为产品版本的唯一来源，并使用 `vMAJOR.MINOR.PATCH-zh-cn` 作为正式发布标签。例如：`v1.0.1-zh-cn`。

## 版本含义

- `MAJOR`：存在不兼容的配置、接口或使用方式变化。
- `MINOR`：增加向后兼容的主要功能。
- `PATCH`：兼容性适配、问题修复、翻译完善或不改变主要接口的小型改进。

每次正式代码发布都必须递增产品版本。当前 GTA `1.73 / 1158.13` 兼容性更新从 `1.0.0` 递增到 `1.0.1`；后续修复依次为 `1.0.2`、`1.0.3`。科兹中心豪劫支持作为向后兼容的新功能升级到 `1.1.0`；存在不兼容变化时才升级到 `2.0.0`。

历史标签 `v1.0.0-zh-cn.1` 至 `v1.0.0-zh-cn.4` 采用了旧规则，将多个代码版本错误地记录为 `1.0.0`。这些已发布标签作为历史记录保留，不复用。从本次修正开始，当前产品版本为 `1.0.1`，标签不再追加发行修订号。

## 单一版本来源

- 根目录 `VERSION` 保存当前产品版本。
- CMake 从 `VERSION` 设置 `PROJECT_VERSION`，不再维护独立的硬编码版本。
- 构建时通过 `YIMMENU_BUILD_TAG` 嵌入完整标签；本地未指定时使用 `v<version>-zh-cn-dev`。
- 启动日志和 Classic 界面显示完整构建标签。
- CI/CD 会校验标签必须与 `VERSION` 生成的 `v<version>-zh-cn` 完全一致。
- 正式 Release 的 DLL 使用 `YimMenuV2-v<version>-zh-cn.dll`；工作流 artifact 包名使用 `binary-v<version>-zh-cn-<完整 Git SHA>`，避免不同提交之间重名。
- 每个正式标签只执行一次 Windows 原生构建；发布任务复用已经验证并上传的 DLL，不再运行第二次相同构建。Zig 交叉编译保留为本地白盒检查手段，不作为发布门禁或发布产物来源。
- Windows 发布构建通过 `sccache` 和 GitHub Actions 缓存按编译输入内容复用未变化的 C/C++ 对象；首次冷构建仍会完整编译，后续标签才会逐步受益。缓存未命中或缓存服务不可用时会回退到正常编译，DLL/PDB 检查和 Release 门禁不会跳过。
- 为使 MSVC ABI 的调试信息可安全缓存，发布构建使用 CMake `CMP0141=NEW` 和 `Embedded` 调试信息格式；每次构建都会输出缓存命中统计，便于用实际耗时评估效果。

## 准备发布

完成代码提交和验证后，在干净的 `main` 上运行：

```bash
scripts/prepare-release.sh patch
```

参数可以是 `major`、`minor` 或 `patch`。脚本会更新 `VERSION`、创建版本提交，并创建对应的唯一附注标签，但不会推送。复核提交和标签后再执行脚本输出的两条 `git push` 命令。标签推送才会触发 CI/CD。构建或发布失败时修复问题并递增 `PATCH`，不为同一版本增加第二套编号。
