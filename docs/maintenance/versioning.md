# 版本与发布规则

中文维护版使用 `VERSION` 作为产品版本的唯一来源，并使用 `vMAJOR.MINOR.PATCH-zh-cn.REVISION` 作为正式发布标签。例如：`v1.1.0-zh-cn.1`。

## 版本含义

- `MAJOR`：存在不兼容的配置、接口或使用方式变化。
- `MINOR`：适配新的 GTA 版本、吸收重要上游功能或增加明显的用户功能。
- `PATCH`：修复问题、完善翻译或进行不改变主要能力的小型改进。
- `REVISION`：同一个产品版本的发行修订号。仅在重新构建、修复发布流程或替换同版本构建时递增；产品版本变化后重置为 `1`。

正常发布不能只增加 `REVISION`。如果源代码或用户可见行为发生变化，必须至少增加 `PATCH`。

历史标签 `v1.0.0-zh-cn.1` 至 `v1.0.0-zh-cn.4` 采用了旧规则，将多个代码版本错误地记录为 `1.0.0`。这些标签作为不可变发布记录保留，不重写、不复用。从 GTA `1.73 / 1158.13` 兼容性里程碑开始，产品版本为 `1.1.0`。

## 单一版本来源

- 根目录 `VERSION` 保存当前产品版本。
- CMake 从 `VERSION` 设置 `PROJECT_VERSION`，不再维护独立的硬编码版本。
- 构建时通过 `YIMMENU_BUILD_TAG` 嵌入完整标签；本地未指定时使用 `v<version>-zh-cn.dev`。
- 启动日志和 Classic 界面显示完整构建标签。
- CI/CD 会校验标签中的产品版本必须与 `VERSION` 完全一致，发行修订号必须为正整数。

## 准备发布

完成代码提交和验证后，在干净的 `main` 上运行：

```bash
scripts/prepare-release.sh patch
```

参数可以是 `major`、`minor` 或 `patch`。脚本会更新 `VERSION`、创建版本提交，并创建发行修订号为 `1` 的附注标签，但不会推送。复核提交和标签后再执行脚本输出的两条 `git push` 命令。标签推送才会触发 CI/CD。

同一产品版本确需重新发行时，不运行版本递增脚本；应在确认原因并记录后，手动创建下一个 `-zh-cn.REVISION` 标签。
