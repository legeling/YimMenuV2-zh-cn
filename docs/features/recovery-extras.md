# 账号进度补充功能

本文档记录中文维护版吸收并加固的账号进度、服装与载具辅助功能。功能面向 GTA 5: Enhanced `1.73 / 1158.13`，代码已加入菜单，但仍需 Windows 原生构建和游戏实机验证。

## 功能入口

| 菜单 | 功能 | 写入类型 |
| --- | --- | --- |
| `账号进度 -> 基础` | 请求保存当前在线进度 | `STAT_SAVE` Native |
| `账号进度 -> 数据编辑器` | 读写 `INT64`、`UINT64`、64 位 Packed Stat、用户 ID、位置和日期 | Stat 缓存、`STAT_INCREMENT`、对应 Stat Native |
| `账号进度 -> 产业` | 显示七项产业实时保险箱余额并领取所选收益 | Script Global 结构与请求 |
| `账号进度 -> 产业` | 补满夜总会人气、清除三项洗钱生意热度 | 命名 Stat、Packed Int |
| `账号进度 -> 产业` | 完成贝克女士故事和致幻剂实验室流程 | 命名 Stat |
| `账号进度 -> 商店` | 修改枪支厢型车 1-10 号武器槽位 | Tunable |
| `账号进度 -> 合约` | 德瑞博士、当当钟农场突袭、奥斯卡、无路可逃跳过前置 | 命名 Stat、Packed Int/Bool |
| `账号进度 -> 合约` | 选择改装铺合约并跳过前置 | 命名 Stat |
| `账号进度 -> 解锁中心` | 分批解锁限时物品、特殊涂装、职业进度和奖章 | 命名 Stat、Packed Int/Bool |
| `账号进度 -> 解锁中心` | 跳过 17 项产业与场所引导、解锁编号 1-77 的平台成就 | Packed Bool、Achievement Native |
| `角色 -> 服装编辑器` | 编辑组件与配件、随机穿搭、保存和读取服装 | Ped Native、本地 JSON |
| `载具 -> 基础 -> 工具` | 永久删除当前已呼出的个人载具 | Script Global 请求 |

| `载具 -> 基础 -> 工具` | 重置技工与个人载具配送冷却 | Script Global Timer |

## 实现约束

- 所有功能只在 GTA 在线模式战局中执行，不在故事模式写入线上进度。
- Packed Stat 和个人载具删除请求按 `1.73 / 1158.13` 记录；游戏更新后必须重新核对索引和全局变量。
- 64 位 Packed Stat 固定拆成四个 16 位块读写，单次操作执行四次 Native 调用，时间和内存开销均为 `O(1)`，避免把高位数据截断到有符号 32 位参数。
- 游戏没有直接持久化 `INT64` / `UINT64` 的 setter Native；数据编辑器先把本地值设置为目标值减一，再调用 `STAT_INCREMENT(..., 1.0f)` 进入游戏保存路径。该行为仍需重新登录验证，不能视为服务器保存保证。
- 数据编辑器的剪贴板导入限制为 1 MiB 和 4096 行，Packed 范围单次最多处理 4096 项；解析时间为 `O(n)`，额外内存不超过剪贴板副本及固定大小字段数组。
- 日期输入按公历月份、闰年、时分秒和毫秒范围校验；位置固定解析三个逗号分隔浮点值，用户 ID 只接受十进制数字。
- 持久进度写入会先把旧值记入日志，但 Rockstar 保存后不保证能够回滚。
- 当当钟农场突袭由五项写入组成，必须保持为单独按钮，不与其他合约批量执行。
- 改装铺合约要求先在面板上接取合约，并在菜单中选择相同项目。
- 删除个人载具只接受当前已呼出的载具；确认后执行前会再次核对车辆 ID，操作不可撤销。
- 枪支厢型车会先检查可调参数缓存，缓存未完成时不会写入空地址。
- 产业余额只读取当前玩家的 `GPBD_FM` / `GPBD_FM_2` 数据；结构未加载、玩家无效或余额为零时不会提交领取请求。
- 限时物品每次最多处理 200 个打包布尔项，职业进度每次最多处理 10 个目录项，奖章每次只处理 1 个目录项；长范围每 50 次访问主动让出脚本纤程。
- 解锁目录使用固定大小值对象，不为每个职业与奖章目录项分别分配堆对象。首次扫描复杂度与目录及打包范围总长度线性相关，限时物品索引去重为 `O(n log n)`，内存上限由内置固定目录决定。
- 批处理游标可从菜单重置；重置后会重新扫描当前角色，避免角色切换后沿用旧进度。
- 平台成就使用游戏 Native 提交单个编号，不使用社区实现中的裸 Script Global。
- 座位、车门和液压命令只作用于当前载具或最近驾驶的有效载具；液压轮位限制为四个受支持索引。
- 服装文件只允许保存在 `saved_outfits` 根目录或其单层子文件夹；拒绝绝对路径、目录穿越和 Windows 非法文件名。
- 服装读取仅接受不超过 1 MB 的 JSON，忽略未知组件并按当前角色模型的实际范围裁剪模型和纹理编号；角色模型不一致时拒绝应用。
- 服装与文件夹列表分别限制为最多 1000 项并排序，刷新复杂度为 `O(n log n)`、内存为 `O(n)`，其中 `n <= 1000`。
- 保存服装先写同目录临时文件，再使用 Windows 原子替换覆盖目标文件，失败时清理临时文件。

## 数据来源与验证边界

初始功能取自 `9d8fb0d`，目录与辅助逻辑复核并锁定到 lonelybud/YimMenuV2 的 `fbf441c858e8a6ac25b7b958ecfa00e9a4b22f10` 快照。服装编辑器随后同步官方 PR #865 的保存与读取能力，并增加中文界面、输入边界、文件大小、路径和列表容量检查。数据编辑器先锁定并吸收官方 PR #1069 的 `74a6c1d99dd1610c31b5ea2eaceafb438df5196f`，随后复核并同步正式提交 `3ad9b2a35a3abc19140473e7e8d01669e60166df`；保留 64 位持久化思路以及新增的用户 ID、位置和日期支持，同时继续使用有定义的有符号位模式回绕、有界解析和公共 Packed Stat 辅助函数。中文维护版没有复制社区实现中的无限批量写入架构，而是重新拆分为命令、中文菜单组、固定批次和带前置检查的执行逻辑；职业与奖章目录保留来源注释，并修正了原目录中 `7559 -> 7553` 的倒序范围，同时把跨越 789 个编号的可疑打包范围收窄为两个端点，避免覆盖无关进度。

当前静态检查和本地交叉编译不能证明 Rockstar 服务器保存行为、任务面板刷新或个人载具永久删除可用。发布前至少需要验证：

1. Windows 原生 Clang 全量构建。
2. 每个按钮在无产业、无任务或无当前载具时的失败行为。
3. 写入后切换战局并重新登录，确认进度状态一致。
4. 删除载具使用测试车辆验证，确认请求不会作用于其他车位。
5. 男女角色分别跑完限时物品批次，确认性别专属目录和角色切换重置行为。
6. 奖章逐项写入时观察交易提示，确认没有触发统计写入限流。
7. 保存、覆盖、读取不同角色模型的服装文件，并验证发型开关、配件清除和无效 JSON 的失败行为。
8. 分别写入 `INT64` / `UINT64` 的零值、正负边界和高 32 位非零值，重新登录后核对持久化结果；Packed Stat 同时核对 64 个 bit 位。
